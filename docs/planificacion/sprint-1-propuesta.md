# Sprint 1 — propuesta de planificación documental

## Propósito

Consolidar la base documental y de diseño de TZISCA antes del desarrollo. Esta propuesta registra trabajo documental verificable; no declara implementación de software.

## Trabajo realizado o documentado

- Estructura del repositorio para documentación, implementación futura y pruebas.
- Propuesta general del proyecto y definición de actores: Cliente, Administrador general, Recepción y cabinas, y Proveedor de tratamiento.
- Reglas de negocio RN-01 a RN-108.
- Casos de uso CU-01 a CU-43.
- Criterios de aceptación documentados.
- Modelo de datos vigente de 19 entidades, con schemas, PK, FK y cardinalidades.
- Diseño del contrato API REST `/api/v1`: 14 módulos y 68 endpoints documentados.
- Arquitectura propuesta Angular → ASP.NET Core REST API → SQL Server.
- Diagramas de arquitectura, flujos, secuencias, casos de uso, estados y modelos ER como material de diseño.
- Diseño de vistas por los cuatro roles, como prototipos y referencias visuales.
- Preparación documental para el inicio del desarrollo.

## Entregables propuestos

| Entregable | Resultado esperado |
| --- | --- |
| Documentación funcional | Propuesta, reglas de negocio, casos de uso y criterios de aceptación consultables |
| Diseño técnico | Diccionario de datos, arquitectura y contrato API coherentes |
| Diagramas | Inventario, correcciones propuestas y modelos ER revisables |
| Vistas | Prototipos clasificados por rol, sin afirmar implementación |

## Pendientes del siguiente trabajo

- Backend.
- Frontend.
- Integración y verificación SQL.
- Endpoints.
- Pruebas.

## Criterio de cierre propuesto

El Sprint 1 puede considerarse cerrado cuando los documentos, diagramas y vistas hayan sido revisados y aprobados como base de implementación. La construcción de código, base de datos ejecutable y pruebas pertenece a etapas posteriores.
