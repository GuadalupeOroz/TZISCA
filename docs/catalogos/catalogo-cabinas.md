# CATÁLOGO DE CABINAS Y SERVICIOS

TZISCA | Propuesta funcional para el sistema de spa

| Este catálogo define los tipos de cabina y los servicios o experiencias de spa considerados para TZISCA. No incluye productos físicos. Cada cabina se administra como un recurso configurable con capacidad, características, equipamiento y compatibilidades que deberán corresponder a datos reales validados por el spa. Las recomendaciones de salud son información general y no constituyen diagnóstico, prescripción ni valoración médica. |

## 11. Estados de las cabinas

Cabina conserva dos campos distintos: activo indica si la cabina está habilitada en el sistema y estado representa su condición operativa actual. Los estados permitidos son DISPONIBLE, OCUPADA, LIMPIEZA y MANTENIMIENTO.

| Clasificación | Estado | Descripción |
| --- | --- | --- |
| Operativo | DISPONIBLE | Cabina activa y elegible para validar una Cita. |
| Operativo | OCUPADA | Cabina en uso; no se ofrece durante la ocupación. |
| Operativo | LIMPIEZA | Cabina temporalmente no disponible por limpieza. |
| Operativo | MANTENIMIENTO | Cabina temporalmente no disponible por mantenimiento. |
| Administrativo | activo | BIT separado del estado: 1 habilita la Cabina y 0 la deshabilita. |

## 12. Coherencia con el Diccionario de Datos

- tipo de Cabina clasifica las cabinas físicas en Masaje, Facial, Hidroterapia, Sauna, Integral o multifuncional y Sal o haloterapia.

- Cabina representa el recurso físico y conserva capacidad, características, equipamiento y estado operativo persistente validados.

- Tratamiento representa cada servicio o experiencia de spa y conserva precio_base y moneda cuando hayan sido validados comercialmente.

- compatibilidad de cabina registra las relaciones activas de compatibilidad entre cada Tratamiento y las Cabinas en las que puede realizarse.

- Modalidad de cobro: Tratamiento.precio_base se interpreta por persona; el MVP no aplica cargos adicionales.

Nota: El catálogo podrá ampliarse desde el panel administrativo con nuevos tipos de cabina, servicios y relaciones de compatibilidad sin modificar la estructura conceptual del sistema.

## 13. Historial y reglas operativas

- Cada cambio de Cabina.estado se registra en EstadoCabina mediante operacion.TR_Cabina_CambioEstado.

- Una Cabina con activo = 0 no se ofrece aunque su último estado haya sido DISPONIBLE.

- Una Cabina activa solo se ofrece si estado = DISPONIBLE, es compatible, tiene capacidad y no se traslapa con CitaCabina.

- La recomendación prioriza cabina especializada sobre multifuncional después de compatibilidad, capacidad, estado, disponibilidad y preferencias; luego usa prioridad e id_cabina ascendente.

- Este catálogo describe tipos funcionales como atributos de Cabina y no crea una entidad adicional.
